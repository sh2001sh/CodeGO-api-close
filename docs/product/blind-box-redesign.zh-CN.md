# CodeGo 盲盒与奖池改造方案

目标是控制成本、讲清规则，让奖品对真实 API 用户有用。消费额度和套餐为主，可以加入限额模型体验、渠道主赞助及少量优惠；不提供付费工具，也不为奖池新建工具产品。一期代码实现消费额度、固定额度套餐、有限批次、冻结规格、完整准备金及消费回馈资格；线上奖池、价格、概率和存量权益尚未修改，发布需单独执行。

推荐先上线免费消费回馈盒，再开放有真实赞助预算的模型探索盒。付费盒如保留，应当是“确定消费额度＋小额随机奖励”的充值活动。约 10% 的利润空间不能支持大幅、普遍的随机赠额，不能用虚构奖品价格掩盖用户得到的额度不足。

## 奖品选择

| 奖品 | 用户实际得到什么 | 成本与限制 |
|---|---|---|
| 小额消费额度 | 可立即用于 API 消费的额度。 | 按全部被使用核算成本；写清范围及消费、转赠、退款限制，不把未用额度当作利润。 |
| 固定额度套餐 | 有明确总额度、期限和模型范围的新版套餐。 | 冻结规格，与余额同口径扣费，没有十倍扣费、刷新次数或新倍率卡；按全额使用核算。 |
| 模型体验卡 | 试用指定编程、推理、图像或音频模型。 | 预留总成本预算，限制单次 token、图像数量/尺寸、音频时长及并发；显示额度与扣费方式，不能只写“免费 10 次”。需要新增结算能力。 |
| 渠道主赞助体验卡 | 体验渠道主预付预算支持的公开渠道。 | 只免除协议约定的结算款，其他成本仍核算；预算先冻结，无真实预算不发卡。标明赞助者，不影响评分或自然排名。 |
| 封顶消费优惠券 | 在指定模型/分组消费时抵扣费用。 | 显示门槛、期限、抵扣上限，与邀请、套餐等优惠共同核算；不发无限折扣，不将未核销券记作到账现金。 |
| 新版套餐延期券，可选 | 本人未到期的固定额度套餐多用几天，额度不增加。 | 仅限允许的新套餐，例如延长 7 天、每套餐最多一次；会增加实际使用，不能称零成本。无适用套餐时按公开规则提供同档替代奖品。 |

一期先做消费额度、固定额度套餐；体验与赞助卡在预算和结算能力真实可用后加入。优惠券、延期券只是补充，不占付费盒的大多数奖项。没有适用套餐的用户不能抽到无法使用且没有替代规则的延期券。

套餐有效期从领取成功或主动激活的明确时点起算；如有激活期限，购买前公布。体验卡展示模型、渠道、预算、单次限制、期限及消费记录。价值由用户判断，不宣传不可兑现的“价值 ¥99”。

已有套餐、刷新次数、倍率卡、旧库存和旧道具按原承诺履约。明确不新增套餐倍率卡；其他旧奖品是否停止新发行，逐项确定，未答复不当作已确认。新版奖池建议不采用零时卡、递归再抽、积分、碎片、宠物或每日幸运号。

## 三类奖池

| 奖池 | 获取方式 | 奖品组合 | 成本来源 |
|---|---|---|---|
| 消费回馈盒，优先上线 | 已结算、符合资格的真实付费消费后免费领取。 | 小额消费额度、固定额度套餐，后续加入体验。 | 从实际剩余正贡献拨活动预算，其他促销共同占用；不按充值额或奖励消费循环发盒。 |
| 模型探索盒 | 按编程、推理、多模态方向选择，优先免费领取。 | 方向内的渠道主赞助体验，可有少量平台补贴。 | 赞助预算先冻结，平台补贴另列；停止新投放不影响已领权益。 |
| 额度回馈盒，付费可选 | 购买确定数量的消费额度，同时揭晓附加奖励。 | 确定基础额度＋随机小额额度、体验或固定额度套餐。 | 额度销售的贡献余量；赠额较小，不能宣传必赚或高回报。 |

模型探索盒按当前可用模型/渠道过滤，用户避开没有需求的方向。赞助内容显式标注，不伪装平台推荐或官方认证。领取后渠道主不能撤回预算、降低额度、收紧承诺；停用或无法兑现时，用预留预算按公布规则补偿。

付费盒旁保留普通充值入口。基础权益若有不同于余额的期限、范围或扣费规则，不能宣称与余额等值。可以直接发同口径消费额度；如果发限期套餐，必须在付款前说明区别。

## 10% 利润空间下的核算

先明确“利润 10%”是收入毛利率还是采购成本加价率。若是收入毛利率，可暂按消费价值 90% 的采购成本测算；若是成本加价 10%，成本占收入约 90.91%。实际要核算模型成本、渠道主分账与活动叠加，不能把假设当通用价格。

同币种、同消费口径下，设售价 P、确定额度面值 B、随机奖励平均面值 E、审核成本系数 c、支付及其他可归属费用 F、目标贡献 M，则应满足：
`c × (B + E) + F + M ≤ P`。
不同成本或赞助来源的奖品分别求和；优惠券按完全核销核算预算，旧保底、未开库存和固定费用另计。

若 B=P、c=0.9，不计任何其他费用时，随机额度平均面值的最大空间仅为 P 的约 11.11%；保留利润、手续费后空间更小。缩短期限不会自动创造用户价值，也不能靠用户忘记使用证明成本安全。

### 付费活动算式示例

以下不是正式价格。全部用同口径消费单位，折算法币须有明确的服务端兑换口径。每盒售价 5 单位，确定到账 5 单位消费额度，另抽一个奖励；一批 1,000 盒：

| 附加奖励 | 数量 | 初始概率 | 面值合计 | 假设成本系数 0.9 的成本 |
|---|---:|---:|---:|---:|
| 0.05 单位消费额度 | 800 | 80% | 40 | 36 |
| 0.25 单位限额模型体验 | 150 | 15% | 37.5 | 33.75 |
| 1 单位固定额度套餐 | 45 | 4.5% | 45 | 40.5 |
| 5 单位固定额度套餐 | 5 | 0.5% | 25 | 22.5 |
| 合计 | 1,000 | 100% | 147.5 | 132.75 |

全批收入 5,000；基础额度成本 4,500，奖励成本 132.75，余量 367.25。若支付费为收入的 3%（150）、其他可归属费用预算 150，只剩 67.25，约收入的 1.345%，尚未覆盖全部固定费用、退款与异常补偿。各成本假设必须替换为真实数据，这个方案已明显压缩原有 10% 空间。

同样奖品和费用下，成本系数若上升至 0.95，整批余量变成 -190.125。不能把其他渠道的平均毛利拿来支持高成本渠道的体验；成本假设失效时停止新发放，已承诺奖品仍由准备金履约。

每盒有确定的消费额度；限额体验和限期套餐不等于现金，也不全部等同于无限期通用余额。多数人只获小额附加奖励，所以适合充值回馈，不适合靠大奖宣传的独立高价盒。消费权益不能表述为现金盈利。

采用固定数量、均匀不放回抽取，显示初始与当前剩余概率；大奖领完明确为 0，不暗中补回或针对个人调整。整批成本可计算，不代表低销量或大奖先发时必然盈利。发布前准备全额履约预算，不能依赖未来销售支付早期奖品。

### 免费和赞助预算

例如真实付费消费产生 100 单位可分配正贡献，活动最多使用其中 10 单位，奖品成本不能超过 10；不是无条件按营业额送 1%。贡献先扣采购、分账、支付、邀请、套餐优惠及退款等可归属支出。奖励消费和奖励购买不重复产生资格，已发免费资格不能因未来预算不足失效。

渠道主愿意推广可提供真实体验补贴，但赞助并非零成本。平台只在冻结款足够、结算边界明确时发放，单列自身承担费用；不能用未签约、未付预算的渠道主名字填充奖池。

## 兑现、版本与并发

发布产生不可变版本，包含价格单位、基础额度、奖品规格、数量/概率、限制与预算。已发布版本只能停售或产生新版本；草稿带修订号防止管理员覆盖。版本、批次、实际发放内容、资金来源进入开奖记录。

预算、最后一份奖品、扣款、发放和记录同事务处理；失败回滚，稳定请求编号重试返回原结果。预算不足停止新销售/新赠送，不削减已承诺权益。退款、补偿及赞助预算释放不能重复；体验不能绕过渠道/分组权限，成本不能只靠客户端限制。

若新奖励要求仅本人消费、不可提现或转赠，必须以账务来源标记约束全部转账、提现、退款和邀请路径。现有历史冻结款会到期释放，前台写“不可提现”不能实现永久限制；既有来源继续原规则。复用现有账本和通知，不新增积分或资金货币。

旧库存不强制转换、不重新开奖。冻结库存按快照，动态库存维持独立兼容配置；旧赠盒数量、期限、首购和保底不清零。若要冻结旧动态库存，应单独盘点、明确公告及冻结时点，不在发布新池时隐式回填。

## 页面与验收

用户页用“消费回馈、模型探索、额度回馈”区分目的，先显示获取方式与确定所得，再列模型/范围、随机奖品和概率，最后提供领取/购买。付费区突出扣款单位、基础额度限制及剩余概率；免费区展示资格来源。旧库存与历史道具列明来源、数量、期限和原保底。

结果页突出到账额度、套餐规格、限制和使用入口。服务端确认结果后播放动画；超时查询原请求，刷新后可恢复。支持减少动态效果、手机和阿拉伯语布局。

后台提供奖池/批次、奖品、成本/预算、发布记录与统计；按类型显示必要字段，数量自动算概率。发布前预览差异、最大承诺和准备金；统计显示发放、激活、真实使用、到期、补偿、赞助承担与平台净成本，低使用率不能作为盈利卖点。

先实现奖池版本、套餐规格冻结、预算、可视化配置和库存选择，以额度、固定额度套餐验证；预算及结算能力完成后加入体验/赞助卡。延期券可选，不是上线前置条件；不包含任何付费工具开发。

涉及 v3/internal/marketplace、commerce、追加迁移、OpenAPI 及生成文件、用户/后台前端和九语言说明。验收覆盖最后一份奖品并发、概率、权限、非法输入、重复请求、预算临界值、回滚、停售后履约、旧现金延迟/重复回调、旧库存/道具/保底；体验还须验证预算耗尽、单次边界、越权、赞助预算不可撤回及补偿。账务来源限制从真实转账/提现等路径验证。

成本验证覆盖全额使用、低销量、大额奖项先发，不能只算全批售完平均利润。执行真实后端命令 `bash v3/scripts/verify.sh boundaries test lint race integration pgtest atlas`；重新生成接口；前端运行 typecheck、check:api、format:check、test、build，并在隔离容器验桌面、手机及支付替身。方案修订不代表已发布。

## 一期实际执行口径

后台「有限批次」与「旧奖池」分开配置。所有新批次金额为整数 micro-credits，1 credit = 1,000,000 micro-credits，不是人民币或港币。发布从当前管理员钱包扣除「基础额度总额＋所有奖品完整面值」，转到批次独立 promotion_budget 账户；预算上限不等于实际准备金。准备金按面值保守冻结，不使用未经确认的 0.9 采购成本假设。尚未自动投放任何新活动。

草稿保存时由服务器冻结新版标准套餐的额度、期限、模型限制等完整规格。发布该修订号时沿用已经预览的规格，之后只允许停售或复制为新的草稿。套餐在主动激活成功时开始有效期；已发奖品无激活截止期限，不能赠送。旧 ID 套餐奖励路径、已存旧库存、动态池、保底和已付旧现金订单都继续保留。

免费资格按活动发布后的真实消费计算，结算满 7 天后由 worker 每分钟处理。有真实支付回调证据、无已确认或处理中退款、已知采购成本、来自本人单笔实付充值或已付新版套餐的消费才纳入；跨来源混合、旧未知来源和奖励消费保守排除。先扣采购、渠道主收益和费用、后台确认的其他可归属费用以及邀请奖励的最大已承诺预算，再按剩余正贡献最多 10% 计算资格；按批次最大奖品面值为每个资格准备贡献，提前占用名额，全局每笔资金消费仅归因一次。未来退款不撤销已经取得的资格，由已经冻结的活动预算承担。

新付费盒购买即揭晓，基础与随机消费额度均永久仅供本人 API 使用，不可用于任何产品购买、再抽盲盒、转赠或退款，不把内部钱包购买当作新的现金营业收入。普通充值入口保留，付款前明确展示这些差异。

停售不影响已发免费资格领取、已发套餐激活或请求重试。预算不会因停售自动释放，以免撤销履约准备金；统计中的「已兑现准备金」是发放的完整面值，不等于已经实际消耗的采购成本或净利润。后台另展示发放、套餐激活和真实 API 使用数量。

模型体验、赞助卡、优惠券和延期券仍属后续能力，一期不冒充已支持，不新增工具、积分、宠物、刷新次数或倍率卡。正式投放前仍需管理员使用真实活动资金、设置实际费用并确认发布。
