# 正式网站能力与 OpenRouter 对照

核对日期：2026-10-15。范围是当前工作区代码，不代表这些改动已经部署。

## 结论与建议顺序

CodeGo 已有统一模型网关、分组市场、店铺、评分举报、渠道主工作台、使用账单、单模型网页对话和部分性能图表。下一阶段应优先把“选模型 → 试用 → 接入 → 核对费用 → 获得支持”连通，再增加榜单和对比工具。无需重新建设第二套聊天或市场。

## 榜单应怎样定义

每个榜单都需要返回时间窗、时区、更新时间、指标单位、样本数、数据覆盖范围与并列规则。榜单只使用有权公开的聚合数据，不公开个人 Key、对话、收入或精确活跃用户身份。

| 榜单 | 推荐指标 | 必须说明的限制 |
| --- | --- | --- |
| 热度 | 成功请求数或实际处理 Token，二者独立切换 | 本站流量；Token 分词器不同，不能直接解释为能力高低；排除内部探针与管理员压测 |
| 增长 | 本期相对上一等长周期的增幅，同时展示绝对增量 | 上期为零或样本过少显示“新上榜/样本不足”，不生成无穷大增长 |
| 可靠性 | 成功数/纳入统计的请求数，辅以失败数 | 统一取消、4xx、上游5xx、重试的纳入规则；低样本不占第一名；探针和真实调用分别统计 |
| 首字速度 | 有效首字 TTFT P50/P95 | 区分单次上游尝试与包含重试的端到端耗时；缺数据排在有效样本后；无输出失败不记作零延迟 |
| 生成速度 | 实际输出 Token/有效生成时间，显示分位数及样本量 | 不能用总耗时简单代替生成时间；推理等待、网络、长短请求会影响比较 |
| 价格 | 指定模型、分组、输入/输出/缓存比例后的标准任务成本 | 显示 credits 与计量单位；已含分组倍率；Fast 2×、UltraFast 6×只乘一次；私人优惠不泄露 |
| 店铺信誉 | 实际付费使用者的星级、有效评价数、近期可靠性 | 禁止自评；一人一店一票可改；少量五星不能压过大量稳定服务，可用置信下界/收缩平均并公布方法 |
| 场景能力 | 有来源的独立评测或用户主动分类 | 编程、长文、图像等不是从模型名猜出；版本可追溯；不得未经授权复制第三方评分 |

防刷应从计量来源入手：仅纳入最终结算且不重复的请求，去掉回滚/测试流量；自用量、异常同源流量和批量空请求单独识别。财务原始账本不能为榜单清洗而改写。先积累可信聚合再推出应用榜，避免为了“完整”填充演示数据。

## 文档本轮补充范围

保留既有快速开始、认证、SDK 接入、计费、套餐、分组、路由池、评分、渠道主、API、流式、错误、生产安全及更新文章，新增以下专题，支持简体、香港繁体、英语、法语、俄语、日语、越南语：

1. 从 OpenRouter 迁移：`/api/v1` 与本站 `/v1` 的差别、重新查模型 ID、专用参数/SDK/排名归因的兼容边界。
2. 请求参数与上下文：不同协议的输入结构、采样、输出上限、历史、工具与推理预算。
3. SDK 流式调用：Python/Node.js/cURL，SSE 终止、空 choices 的 usage 帧、中断及重试。
4. 工具调用与结构化输出：声明工具、回传结果、实际调用 ID、循环上限、JSON Schema 与输出校验。
5. 图像与多模态：图像输入样例、格式和能力检查、网页尚未完成的附件功能边界。
6. 网页对话与历史：入口、实际计费、编辑重发、本机存储与云端同步的区别。
7. 模型图表与排名口径：热度、成功率、TTFT、TPS、时间窗与缺样本的含义。
8. 社区、支持与反馈：用户提供的 X/Discord、脱敏反馈、状态与政策入口。

修正 Fast 协议值为 `priority`，新增 `ultrafast` 样例及 2×/6×计算说明。6×沿用用户确认的本站配置，不标注为已独立核实的上游官方价格。所有示例使用环境变量，不自动发起付费请求；可切换 cURL/Python/Node.js。

## 正式经营仍需提供的事实

以下内容不能由代码或参考网站替经营者决定，也不能凭空填入公开政策：

- 支持与安全/隐私联系邮箱、有人处理的时间、实际升级渠道；Discord 邀请是否长期有效。
- 用户数据、请求元数据和可选提示词日志各自的保存期限、删除申请流程、备份删除边界、上游处理商和地区；哪些是渠道主声明，哪些有合同证据。
- 退款资格、赠额/套餐退款处理、处理时间、费用和争议窗口；支付失败、拒付及冻结申诉流程。
- 可接受使用规则、违规渠道处置与复核流程；模型内容免责声明与投诉流程。
- 实际可承诺的服务等级、监控口径、维护通知及事故历史；没有协议前不写 SLA 百分比。
- 模型信息更新责任人、版本与下架通知周期；API 版本兼容和弃用周期。
- 如果服务特定国家或企业，核定适用地区、主体披露、税务及数据处理要求后再公开。

已知现有风险：`features/pricing/lib/mock-stats.ts` 的 `buildRateLimits` 按模型与分组种子生成模拟 RPM/TPM/RPD；`model-metadata.ts` 含能力与隐私等推断逻辑。模型详情中的能力、速率限制、数据留存/训练信息应逐项核验来源；模拟限额应移除或明确标注，不得当作真实限额；未核实的值不能包装为渠道保证。本轮只记录此问题，不借补文档重写整套模型元数据。
