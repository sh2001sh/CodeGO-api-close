# CodeGo 全站重设计：总体方案

版本：2026-10-16 · 设计规范 codego-redesign-documentation-v2

## 交付与事实边界
本方案补充既有 docs/redesign。首页为可操作 demo，其余页面交付实施规范。原仓库保持只读；当前源码存在未发布修改，文档中的“现有”仅表示本地可见。首页预览使用真实模型名称，示例不构成上架、价格、性能或服务承诺。

正式阅读入口为 design.html，首页入口为 index.html。Markdown 专题承载同一方案的可编辑正文。正文中的解释只用于设计交接，产品界面遵循第12章的文案规则。

## 产品结构与首要闭环
CodeGo 的核心是统一模型网关与渠道市场。用户闭环为：选模型 → 核对分组与来源 → 试用 → 创建受限 Key → 接入 → 核对费用 → 排障与支持。渠道主闭环为：创建渠道 → 核验披露 → 发布 → 监测 → 收益对账。管理员负责审核与治理，权限独立。

避免把 API 使用、分组市场、店铺、路由池混成同一种实体：
| 实体 | 稳定身份 | 展示职责 |
| --- | --- | --- |
| 模型 | 实际 model ID 与版本 | 能力、上下文、协议及价格组成 |
| 渠道 | 原数字渠道 ID | 上游、健康、额度及调度配置 |
| 分组 | 既有分组标识 | 可访问范围、倍率及披露 |
| 店铺 | 渠道主聚合身份 | 渠道集合、评价、信誉及举报 |
| 路由池 | 既有池 ID | 用户授权范围内的成员和策略 |
| Key | 账号下的稳定 Key ID | 权限、额度、有效期、审计 |
| 订单 | 不可变订单快照 | 实付、赠额、币种及结算依据 |

## 三种使用场景
首页负责让访客感受“汇流”，用大字、真实品牌、路由机制与可操作模型入口建立认知。控制台负责完成任务，表达集中在选中、提交和数据层次。文档与政策负责阅读，保持稳定页面、可引用标题和足够行长，避免首页动效进入长篇阅读。

首页的视觉重心是 CodeGo 大字和铜橙路由场，控制台的视觉重心是当前任务和数据。两者共用色彩、字体、图标及动效参数，不强行共用容器外观。

## 信息架构
| 空间 | 一级入口 | 二级组织 | 角色 |
| --- | --- | --- | --- |
| 公开 | 模型、市场、状态、文档 | 详情、店铺、分组、文章 | 访客；按站点配置允许登录门槛 |
| 个人 | 概览、对话、Key、日志、钱包 | 模型分析、会话、任务、发票 | 登录用户 |
| 渠道主 | 工作台 | 渠道、探测、收益、店铺设置 | 所有者，仅自身资源 |
| 后台 | 治理、渠道、模型、用户、审计 | 审核、部署、批量操作 | 管理员，服务端再次授权 |
| 系统设置 | 站点、认证、账务、模型、安全、内容、运维 | 实际 section 注册项 | 管理员 |
| 规划 | 榜单、对比、关注、团队 | 满足数据与业务依赖后开放 | 按阶段开放 |

公开 /market、渠道主 /channel-workbench、管理员 /marketplace 具有不同受众。不得用同一个无权限区分的页面替代。/chat/$chatId 为既有外部预设，不承担新原生多会话路由职责。

## 首屏与全局阅读顺序
1. 公开页：标志及导航 → 当前页面标题 → 主内容和主操作 → 可信来源入口 → 必要页脚。
2. 登录页：稳定账号外壳 → 当前任务 → 表单 → 结果与返回。登录目标必须经过本站安全路径校验。
3. 控制台：当前空间 → 面包屑与页名 → 筛选及主操作 → 数据 → 分页及详情。
4. 设置：分类导航 → 当前设置标题 → 分组字段 → 保存区。未保存变更离开时确认，失败保留输入。

## 全站变更策略
先替换存在误导风险的模拟限额和无来源承诺，再改视觉。保持服务器协议、价格快照、订单和权限语义。视觉改造不顺带重写网关或迁移账本。

幸运号与拼团入口已跳转钱包；设计保留历史履约或记录入口，禁止重新出现购买或参与按钮。发票和充值等别名在覆盖表中记录实际目标。
