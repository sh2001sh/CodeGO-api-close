## 🎯 核心问题与瓶颈

### 问题 1: 主力渠道负载过高导致慢请求

#### ling 渠道（Plus分组）

**数据**：
- 总请求：963,489 次（占 GPT 总量 33.2%）
- 慢请求：59,021 次（6.13%）
- 慢请求平均耗时：111秒
- 成功率：91.71%（略低于 GPT 平均 93.6%）

**主力模型分布**：
- gpt-5.6-sol: 768,302 次（79.7%）
- gpt-5.6-terra: 160,189 次（16.6%）
- gpt-5.5: 32,404 次（3.4%）

**问题根源**：
- ❌ **Plus分组 路由池被禁用**，所有 Plus分组 请求只能走 ling 渠道
- ❌ 负载过高导致 6.13% 的请求 > 60秒
- ❌ 慢请求平均耗时高达 111秒（1.85分钟）

## ⚡ 优化方案

### 方案 A: 立即优化（0成本，今天完成）

#### A1. 禁用极差渠道 🔴

**立即禁用**：
```sql
-- 24-Codex Plus-0.098x: 41.67% 慢请求 + 56.52% 成功率
UPDATE channels SET status = 0 WHERE name = '24-Codex Plus-0.098x';
```

**影响**：
- 减少 2,047 次请求（其中 853 次慢请求）
- 但这些请求成功率仅 56%，大部分是失败+浪费时间

#### A2. 启用 Plus分组 自动路由池 ⚡⚡⚡

**当前状态**：
- ling 渠道：963,489 次 GPT 请求，59,021 次慢请求（6.13%）
- Plus分组 路由池**被禁用**，无法分流

**操作步骤**：
1. 在管理后台启用 "Plus分组 自动路由"
2. 配置权重：
   ```yaml
   multiplier_weight: 20  # 成本权重
   ttft_weight: 50        # TTFT权重（提高）
   success_weight: 20     # 成功率权重
   cache_weight: 10       # 缓存权重
   ```
3. 路由池成员配置：
   - tn (0.12x) - 低成本，性能良好
   - ling (0.81x) - 主力
   - image-niu (1x) - 备用
   - image-tp (1x) - 备用

**预期效果**：
- ✅ ling 的慢请求从 59,021 降至 **~40,000**（-32%）
- ✅ tn 渠道承接 30-40% 的 Plus分组 流量
- ✅ Plus分组 平均耗时从 22秒 降至 **~17秒**（-23%）
- ✅ Plus分组 慢请求占比从 6.13% 降至 **~4%**

**影响规模**：
- 影响 963,489 次 GPT 请求（33.2%）
- 减少约 **19,000 次慢请求**
- 节省用户等待时间：**~50小时/天**

#### A3. 降级/隔离高慢请求占比渠道 ⚠️

**慢请求占比 > 12% 的渠道**：

- 25-Codex Plus-0.08x (12.16%)

```sql
-- GPT 实时性能监控
SELECT 
    l.model_name,
    COUNT(*) as requests,
    ROUND(AVG(l.use_time)) as avg_time,
    COUNT(CASE WHEN l.use_time > 60 THEN 1 END) as slow_requests,
    ROUND(100.0 * COUNT(CASE WHEN l.use_time > 60 THEN 1 END) / COUNT(*), 2) as slow_pct
FROM logs l
WHERE l.created_at > (EXTRACT(EPOCH FROM NOW()) - 3600) * 1000
    AND l.type IN (2, 5)
    AND l.model_name LIKE '%gpt%'
GROUP BY l.model_name
ORDER BY requests DESC;

-- Plus分组 性能监控
SELECT 
    c.name,
    COUNT(*) as requests,
    ROUND(AVG(l.use_time)) as avg_time,
    COUNT(CASE WHEN l.use_time > 60 THEN 1 END) as slow_requests
FROM logs l
JOIN channels c ON l.channel_id = c.id
WHERE l.created_at > (EXTRACT(EPOCH FROM NOW()) - 3600) * 1000
    AND l.model_name LIKE '%gpt%'
    AND c."group" = 'Plus分组'
    AND l.type IN (2, 5)
GROUP BY c.name
ORDER BY requests DESC;
```
